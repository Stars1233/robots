### Fixed: the `moveit2`, `protomotions` and `microduck` envelopes now say the instruction was never read

`MoveIt2Policy`, `ProtoMotionsPolicy` and `MicroduckPolicy` always documented `instruction` as ignored - the planner reads its goal from `target_pose` / `target_joints`, the tracker follows the loaded motion, the gait follows the velocity command - but each left `Policy.reads_instruction` at the `True` default, so `run_policy(..., instruction="pick up the red cube")` echoed `MicroduckPolicy | pick up the red cube` / `Policy complete` and an agent read that as a pick that happened. The three classes now declare `reads_instruction = False` with `instruction_free_actions` naming what they command instead, so the simulation and hardware envelopes append the same `Note: <Policy> does not read the instruction.` sentence the mock earns, and the JSON payload reports `instruction_read: false`. `docs/policies/moveit2.md` says so beside the sentence that already called the instruction ignored.

### Fixed: docs fences import each tool from `strands_robots`, where the name is always the tool

Every docs fence that used a tool spelled it `from strands_robots.tools import use_ros`. That name is also the tool's submodule, and `from strands_robots import Robot` - the first line of nearly every page - imports `strands_robots.mesh`, which imports the `use_ros`, `use_rosbridge` and `use_rtps` submodules; from then on the fence bound the module, and the page's own `use_ros(action=...)` raised `TypeError: 'module' object is not callable`. The eleven fences across ten pages now read the tool off the package root (`from strands_robots import use_ros`), whose lazy export has no same-named submodule to shadow it, and the in-tree ban on the ambiguous spelling now scans docs python fences as well as first-party modules.

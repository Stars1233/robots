### Fixed: the pure-RTPS bridge examples in `docs/rtps-integration.md` and `docs/ros2-integration.md` used to raise on a fresh install. Their first `Robot(..., ros2_transport="rtps")` line left `ros2_commands` at its default, and on that transport an enabled inbound command surface is refused without a `dds_security_config` or the explicit insecure opt-out, so copying the fence produced `ValueError: Refusing to start an inbound joint_command surface on an unsecured DDS graph` before any telemetry flowed. Both fences now construct a telemetry-only bridge (`ros2_commands=False`) and say where the command surface's security config or opt-out is described, so the page runs top to bottom as written.
